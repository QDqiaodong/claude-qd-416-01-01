# 装订车间管理系统

装订车间（装订机 / 工单 / 签样 / 纸张 / 成品）的台账与流转管理。基于 Spring Boot 3.3 + JPA + Vue 3 + Element Plus + MySQL + Redis，docker compose 一键启动。

## 启动

```bash
./start.sh
```

启动后访问 http://127.0.0.1:8246/ 。

> 本次机台状态收敛为固定取值，并新增报修/修好两个动作。老库升级时 schema.sql 不会自动重跑：建议 `docker compose down -v` 后重新 `up -d --build`（会重置数据）。若需保留老库，请手动在库里执行：
>
> ```sql
> -- 1. 先查出历史上自由输入写坏的机台状态（检修/停机/随手词）
> SELECT id, code, name, status FROM machine
>  WHERE status NOT IN ('空闲','运行','维修');
> -- 2. 这些机台在系统里走一次“报修 → 修好”收敛回合法状态后，再加约束
> ALTER TABLE machine
>   ADD CONSTRAINT chk_machine_status CHECK (status IN ('空闲','运行','维修'));
> ```

## 模块

- 装订机：基类 `Machine` 单表继承（`@Inheritance(SINGLE_TABLE)` + 判别列 `machine_type`），子类 `GlueBindMachine`(胶装机) / `SaddleStitchMachine`(骑马钉机) 各具独有字段；编号唯一，运行/维修中禁止改关键参数
  - **状态只有 空闲 / 运行 / 维修 三个固定取值，后端只认这三个**（DB 有 CHECK 约束兜底）；历史脏值机台可在机台页按“异常（非法状态）”筛出来，走一次报修 → 修好收敛
  - **报修（`POST /api/machines/{id}/repair`）**：机名下有正在开印（进行中）的工单时报修不成功，提示点出工单号让班长先收尾或退回；报修生效的同一刻，机台上所有仍停在未过的签样一并作废成退回，已扣的试装纸不还（与签样退回口径一致），机台落维修
  - **修好（`POST /api/machines/{id}/restore`）**：只从维修回到空闲；被连带作废的签样**不自动恢复**，要往下走必须重新开一笔试装
- 工单：状态机 待排→进行中→已完成；运行中的机器不能重复接单（同机进行中工单唯一）；**没有已过签样的工单不能开印**（待排不能推进进行中，也不能一开单就建成进行中）
- 签样（试装签样台，单独成页成账）：每笔记挂哪张待排工单、用哪台装订机、抽哪一种纸、试装几册
  - 胶装机试装必须记书脊厚度，超过该机最大厚度不能写成已过；骑马钉机必须记订针数，超过该机最大针数同样不能写成已过
  - 试装用纸从纸张库存扣：库存不够时签样停在未过、一张都不扣；签样退回后已扣的纸不退回库存
  - 只有空闲/运行机台能开新签样（维修中及历史脏值机台前后端都挡住）；已过签样锁定机台和纸种（开印对的就是试装当时那台机、那种纸）
- 纸张：克重 / 库存 / 预警线；库存不足拦截领纸
- 成品：归属工单必须存在且已完成，**且该工单有已过签样**才能建档入账（签样退回或仍停在未过一律拦住）
  - **入库链固定 待入库 → 已入库**：登记只能是待入库，不能一登记就已入库，也不能从已入库改回或写成别的值（DB 有 CHECK 约束兜底）；数量必须大于 0，非法状态、零/负数量、挂到不存在或未完成工单的请求一律明确报错
  - **已入库即锁定**：归属工单和数量不能再改，不能换单、不能重复入库
  - **待入库换单**：目标工单必须仍是已完成且保留有效的已过签样（锁行当前读，并发的签样退回先提交则换单被拒）；换单留痕原工单（`prev_order_id`），成品页顶部按工单汇总 计划/待入库/已入库/可再登记余量，原单与新单的关系可核对
  - 并发口径：入库 / 换单先锁成品行（`SELECT ... FOR UPDATE`）再锁签样行，两人同时办同一笔成品的入库只成交一笔，另一人拿到明确报错；失败操作整体回滚，不留半条成品记录
  - 老库升级（成品表结构变了）：`docker compose down -v` 后重新 `up -d --build`；需保留老库则先清掉非法状态/非正数量的成品行，再手动执行：
    ```sql
    ALTER TABLE product ADD COLUMN prev_order_id BIGINT;
    ALTER TABLE product ADD CONSTRAINT chk_product_status CHECK (status IN ('待入库','已入库'));
    ALTER TABLE product ADD CONSTRAINT chk_product_qty CHECK (qty > 0);
    ```
- 并发口径：报修 / 开试装 / 开印 / 建档 / 扣纸的判定都在事务内做行锁当前读，且统一**先锁机台行**再锁签样/纸张行；报修与同机台并发提交的新试装在机台行上串行，最终以先提交者为准——报修先生效则试装被拒，试装先提交则报修把它一并作废，不会两边各按自己看到的状态各写一笔
